我用一份 JSON 管住了一个网站

2026 年 11 月 18 日·2 分钟读完
建站工具

这个站最早只是想做一张"门面"，后来发现真正麻烦的不是设计，是改——改一句文案要翻三个文件、换一个主色要动一堆十六进制。

所以我把内容抽成了一份 JSON。

三层结构

现在整个站只有三样东西：

  1. 配置（config.js）：品牌、导航、每一段文案、每个价格、每个问答。
  2. 渲染（render.js）：配置进，HTML 出，纯函数，不碰 DOM。
  3. 外壳（main.js / customizer.js）：读写配置、即时重绘、存到 localStorage。

因为渲染是纯函数，同一份代码能在两个地方跑：浏览器里（实时改）和 Node 里（构建时预渲染）。

// 浏览器
SF.render(cfg, { instant: true })

// 构建时
const parts = SF.renderParts(cfg, { mode })

为什么非要预渲染

纯前端渲染的页面，爬虫拿到的是一张空壳。预览版看着好好的，一搜什么都没有。

预渲染之后，dist/index.html 里躺着的就是完整正文——标题、价格、问答全在 HTML 里。JavaScript 只负责让它可以被改。

好看是运行时的本事，被搜到是构建时的本事，两件事别混在一起。

面板不是编辑器

定制面板不做"保存"这个动作。它只做一件事：改内存里的配置对象，然后让页面重画一次。

真正的保存发生在两个地方：

  • 浏览器把它写进 localStorage（你自己的预览）
  • 你导出 JSON，覆盖 config.js，重新构建（所有人的正式版）

这样就不会出现"后台数据库改了、线上没变"的经典事故。

代价

  • 多了一个构建步骤：改完必须 node build.mjs，忘了就还是旧站。
  • 配置没有类型检查，写错字段名不会报错，只会安静地不显示。
  • 区块只能开关和排序，想做真正奇怪的版式还是得改代码。

值不值？对我来说值——加一个工具、换一次主色，都只要改一行配置，然后重新拖一次 zip。
